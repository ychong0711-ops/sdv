1. 이 프로젝트는 무엇인가?

독일 자동차 회사(BMW, Mercedes-Benz, CARIAD 등)는 차량 내부를 HPC(고성능 컴퓨터)와 Zone ECU(지역 제어기)로 나누어 관리합니다. 이를 SDV(Software Defined Vehicle) 아키텍처라고 합니다.

이 프로젝트는 실제 차량 아키텍처를 €68짜리 보드(Arduino UNO Q)로 1:1 재현한 포트폴리오입니다.

2. 핵심 개념 미리보기

SOME/IP란?

SOME/IP는 Service-Oriented Middleware for IP의 약자로, 차량 내부에서 부품들끼리 "서비스"를 제공하고 요청하는 방식으로 통신합니다.

이 프로젝트에서는 vsomeip 라이브러리 대신 와이어 프로토콜(바이트 형식)을 직접 구현했습니다. 그래서 Wireshark로 캡처하면 실제 차량 통신과 똑같이 보입니다.

💡 초보자 알아두기 vsomeip은 독일 자동차 회사들이 실제로 쓰는 C++ 라이브러리입니다. 이 프로젝트는 라이브러리를 "쓰는 것"이 아니라, 라이브러리가 보내는 "바이트를 직접 만드는 것"을 증명합니다. 면접에서 이것이 핵심 차별점입니다.

CAN-FD란?

CAN은 차량의 오래된 통신 버스이고, CAN-FD는 더 빠르게(최대 2Mbps) 더 많은 데이터를 보내는 개선 버전입니다. 이 프로젝트에서는 졸음 경고를 CAN-FD로 보냅니다.

Safe State란?

차량에서 CPU가 멈추거나 오류가 나면 안전한 상태로 진입해야 합니다. 이 프로젝트에서는 MPU(두뇌)가 멈추면 MCU(실시간 제어기)가 100ms 안에:

  1. CAN으로 경고 프레임을 보냄
  2. LED를 빠르게 깜빡임
  3. Watchdog를 유지하여 리셋되지 않음 (의도적 안전 상태)

4. PC 시뮬레이션으로 첫 실행

하드웨어 없이 PC만으로 SOME/IP 패킷이 어떻게 생성되는지 확인할 수 있습니다.

1 트리거 테스트로 SOME/IP 패킷 보내기

python mpu/ai/trigger_test.py --transport udp --level 85

출력 예시:

[TEST] SOME/IP Notify sent: level=85 (24 bytes)
       hex: 12 34 80 01 00 00 00 09 00 01 00 01 01 01 02 00 55 00 00 00 00 00 00 00
       Wireshark filter: udp.port==30490 && someip
💡 이 바이트를 이해합시다
  • 12 34 = Service ID (서비스 식별자)
  • 80 01 = Event ID (졸음 알림 이벤트)
  • 00 00 00 09 = Length (패킷 길이 = 9바이트)
  • 55 = 졸음 레벨 (85% = 0x55)
  • 나머지 = 패딩 (8바이트 정렬 맞추기)

2 Heartbeat 전송

python mpu/ai/trigger_test.py --transport udp --heartbeat

50ms마다 Heartbeat 패킷(Event ID 0x8002)이 전송됩니다. Ctrl+C로 중지.

3 Wireshark로 확인 (선택)

Wireshark를 설치하고, UDP 포트 30490을 캡처하면 SOME/IP 패킷이 보입니다.

# Wireshark 필터
udp.port == 30490

4 유닛 테스트 실행

pip install pytest
python -m pytest mpu/tests/ -v

5개 테스트가 통과하면 프로토콜 구현이 올바릅니다.

🔍 protocol.py — SOME/IP 패킷은 어떻게 만들어지나?

# mpu/someip/protocol.py (핵심 부분 발췌)

def build_packet(event_id: int, payload: bytes, session_id: int = 1) -> bytes:
    length = len(payload) + 8  # length = payload + 8 (SOME/IP 규칙)
    header = struct.pack(
        "!HHIHHBBBB",         # 빅엔디안, 16바이트
        SERVICE_ID,            # 0x1234
        event_id,              # 0x8001(졸음) 또는 0x8002(heartbeat)
        length,                # payload 길이 + 8
        0x0001,                # client_id
        session_id,            # 세션 번호
        0x01, 0x01, 0x02, 0x00 # 프로토콜/인터페이스/메시지타입/리턴코드
    )
    packet = header + payload
    pad = (8 - (len(packet) % 8)) % 8  # 8바이트 정렬 패딩
    if pad:
        packet += b"\x00" * pad
    return packet

🔍 safety.cpp — MPU가 멈추면 어떻게 하나?

// MCU/src/safety.cpp (핵심 로직)

static void safety_timeout(struct k_timer *timer) {
    if (!safe_state) {
        // MPU에서 heartbeat가 안 왔다 → Safe State 진입!
        enter_safe_state();
    } else {
        // 이미 Safe State → 안전 동작 반복
        can_send_warning(can_dev);    // CAN 경고 프레임 (level=0xFF)
        gpio_pin_toggle_dt(led);     // LED 빠른 점멸
        wdt_feed(wdt, 0);            // Watchdog 유지 (리셋 금지)
    }
}

void safety_kick_watchdog(void) {
    wdt_feed(wdt, 0);                // Watchdog 리셋
    // heartbeat가 복구되면 Safe State 해제
    if (safe_state) {
        safe_state = false;          // NORMAL로 복귀
    }
}
정상 동작 흐름:
MPU (50ms heartbeat) ──SOME/IP──► MCU ──kick──► Watchdog 리셋
                                                  ↓ (100ms 내 heartbeat 없으면)
                                              Safe State 진입
                                                  ↓
                                          CAN 경고 + LED 점멸 + Watchdog 유지

6. 실보드(UNO Q)에서 실행하기

하드웨어가 있다면 다음 단계로 진행합니다.

1 MCU 플래시 (Zephyr 빌드)

# Zephyr SDK + west 필요
west build -b arduino_uno_q MCU
west flash

2 MPU 실행 (UART 터널)

# 실보드는 UART가 기본값 (별도 --transport 지정 불필요)
python mpu/ai/drowsiness.py

# 또는 명시적으로
python mpu/ai/drowsiness.py --transport uart --uart-port /dev/ttyS0

3 Docker로 실행 (선택)

# 실보드 UART 사용 시 환경변수 설정
export SOMEIP_TRANSPORT=uart
export SOMEIP_UART_PORT=/dev/ttyS0

docker compose -f docker/docker-compose.yml up --build
⚠️ 실보드 주의사항
  • UART 포트 경로는 보드마다 다릅니다. dmesg | grep tty로 확인하세요.
  • CAN-FD 트랜시버 모듈이 없다면 루프백으로 테스트하세요.
  • 현재 실보드 검증은 진행 중입니다. PC 시뮬레이션이 더 안정적입니다.

8. 면접에서 활용하는 법

면접관이 묻는 질문과 답변 예시

Q: "이 프로젝트에서 어떤 역할을 했나요?"

A: "독일 SDV 아키텍처(HPC + Zone ECU)를 €68 보드로 재현했습니다. MPU에서 Python으로 SOME/IP 와이어 포맷을 직접 생성하고, MCU에서는 Zephyr 위에서 경량 파서로 수신하여 CAN-FD로 전송하는 전체 파이프라인을 구현했습니다."

Q: "vsomeip를 왜 안 썼나요?"

A: "MCU(Zephyr)에서는 vsomeip의 의존성(Boost, POSIX 소켓 등)이 무거워서, 대신 경량 SOME/IP 파서를 직접 구현했습니다. 와이어 프로토콜 포맷은 vsomeip과 100% 호환되어 Wireshark에서 동일하게 해석됩니다. 이 과정에서 SOME/IP 헤더 구조와 길이 계산을 깊이 이해하게 되었습니다."

Q: "안전 설계는 어떻게 했나요?"

A: "ISO 26262 Safe State 패턴을 적용했습니다. MPU가 50ms마다 heartbeat를 보내고, MCU에서 100ms 내 미수신 시 Safe State로 진입합니다. 진입 시 CAN 경고 프레임 송신, LED 점멸, 그리고 의도적으로 Watchdog를 유지하여 리셋이 아닌 안전 상태를 유지합니다."
